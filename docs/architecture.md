# LavaNotes 设计说明

LavaNotes 从 LavaDesk（原灵月桌面）的桌面便利贴组件拆分而来，作为独立软件开发。本文记录当前实现的关键取舍，方便后续修改时不走回头路。

## 为什么每张便签一个透明窗口

LavaDesk 里的便利贴画在一个铺满屏幕的透明 Canvas 窗口上。为了让 Canvas 不挡住桌面，它常态鼠标穿透、不可聚焦，靠原生命中轮询、临时借焦点、遮挡检测和锁屏/全屏后重建窗口来维持交互；全屏返回拖不动、锁屏后无法输入、输入法失焦等问题都出在这条链路上。

LavaNotes 让每张便签成为一个只比纸张大一圈的透明窗口：

- 焦点、输入法、Alt+Tab、前后顺序都是普通窗口的行为，不需要补偿。
- 纸张外的一圈透明边距（放倾斜后的纸角、胶带、阴影）在 Windows/macOS 上鼠标穿透。Windows 不会可靠地把鼠标移动转发给穿透中的窗口（1.0.0 因此整张便签点不动），所以由主进程轮询光标（在便签窗口上方时 30ms，否则 120ms）：光标在某个便签窗口内时，主进程把窗口内坐标发给页面，页面用 `elementFromPoint` 判断是否落在纸上（`[data-hit]`）并回答，主进程只在纸上时关闭穿透。拖动、缩放期间不穿透；任一鼠标键按住时（`GetAsyncKeyState`）不切换，文字选择拖出纸面也能继续。
- 穿透用 `setIgnoreMouseEvents(true)`，**不带 `forward`**。Windows 上 Electron 的转发靠全局鼠标钩子，把移动消息发给每个“矩形里包含光标”的转发窗口，不管它是否被别的窗口挡住；便签相互重叠时，后面那张会不停按自己的页面设置光标，前面便签上的指针就来回闪。命中判断本来就靠轮询，不需要转发。
- 光标保持安静：纸面、顶栏、边缘和所有按钮都是箭头，正文区域（含内边距）是文本光标，只有胶带是手形，拖动时整张便签显示抓取手形（`data-dragging`）。以前顶栏 grab、按钮 pointer、缝隙 default 交替，划过一排按钮时指针来回变。
- 透明窗口在 Windows 上先以透明度 0 置顶显示一次再回到自己的层级，并在页面加载完成和显示前再次设置透明背景色；否则窗口可能带着不透明的白底出现（electron#40515，LavaDesk 桌面层用同样的处理）。
- 边距只取决于倾斜角，按最大纸张尺寸计算（`getWindowMargin`）。纸张缩放时边距不变，纸在窗口里的位置就不会跳。

### 缩放

Electron 文档说明透明窗口不能用系统方式缩放。右下角折角按下时，主进程先把窗口撑到最大纸张尺寸（透明，看不出来）；拖动过程中渲染进程只改纸张的 CSS 尺寸；松手后主进程按最终尺寸收回窗口并保存。整个过程窗口只变两次。

### 移动

渲染进程在纸条/胶带/纸边按下并移动超过 3px 后发 `dragStart`，之后每帧发 `dragMove`；主进程用 `screen.getCursorScreenPoint()` 计算新位置并 `setPosition`，避免渲染进程坐标在多屏混合 DPI 下的偏差。

### 渲染进程

默认每个便签窗口用 `new BrowserWindow` 单独创建，各有一个渲染进程。1.0.0 让所有便签由一个隐藏 host 页面通过同源 `window.open` 打开以共享渲染进程，但在 Windows 上这样打开的透明窗口出现了不透明白底，1.0.1 起改回经过验证的普通创建方式。共享方式仍保留在代码里，设置环境变量 `LAVANOTES_SHARED_PROCESS=1` 可启用（host 进程崩溃时会重建并重新打开所有可见便签）。

preload 按页面路径（`/note/`、`/manager/`、`/host/`）只暴露对应 API，两种方式通用；主进程按 `webContents.id` 反查便签，每个便签窗口只能操作自己的便签。

## 钉在桌面

1.0.3 起便签上不再有层级开关，只在便签管理 → 设置里选新便签的层级（普通窗口 / 置顶 / 钉在桌面），新便签沿用；从便签上点 + 新建的沿用那张便签的层级。实现与 LavaDesk 桌面层相同的两步 Win32 调用（`src/main/win32.ts`）：

1. `SetWindowLongPtr(GWLP_HWNDPARENT, SHELLDLL_DefView)`：让桌面成为窗口的 owner。Windows 保证被拥有的窗口在 owner 之上，Win+D / Win+M 把它当作桌面的一部分，不会隐藏或最小化。
2. `SetWindowPos(HWND_BOTTOM, SWP_NOACTIVATE)`：压到最底层，即桌面图标之上、所有普通窗口之下。

补充处理：

- 点击编辑时窗口会被激活并抬到最前；失焦后按“最近使用在上”重新排列所有钉住的便签（新的先 `HWND_BOTTOM`）。
- 透明窗口在被遮挡时首次合成可能出错，钉住的便签启动时先以透明度 0 置顶显示，再钉到桌面并恢复透明度。
- 每 3 秒检查钉住的便签 owner 是否仍是当前的 DefView（资源管理器重启会换掉它），不是就重新钉上；窗口被系统意外关闭时，60 秒内最多重开 3 次。
- 非 Windows 平台不提供“钉在桌面”。

## 数据模型

- **只有便签，没有待办**：1.0.3 移除了待办（截止时间、分类、优先级、到期提醒、周复盘）和图钉/自然贴两种固定方式，纸张一律用纸胶带；旧数据里的 `todo`、`paperStyle` 字段在加载时丢弃。顶部的 ✓ 就是完成：主进程记下这张便签正在撕下，窗口播放撕下动画后回报（2.5 秒内没有回报也照样归档），再写入 `archivedAt` 并隐藏。归档的便签在便签管理里筛选“已撕下”可以找到，可以重新贴回（清除 `archivedAt`）或删除。
- **新便签的倾斜和位置**：倾斜按 `ROTATION_SEQUENCE`（`-3.0, 2.4, -1.8, 3.4, -2.6, 2.0`）逐个取，左右交替，序号从已有便签数接着往下数。位置由 `placeNewNote` 从 `newNoteSlots` 里取第一个空位：从工作区右上开始向左排，每张相隔约 0.45 个纸宽、上下交替错开约 0.35 个纸高，每排最多 5 张；下一排再往下约 0.8 个纸高、往左半步，最多 3 排；都保持在工作区内。某个位置 48px 以内已经有便签起点就跳过，所有位置都占了才从头错开 24px 重排。相邻便签大约重叠三分之一。从便签上点 + 也走这套规则，用被点便签所在的屏幕。1.0.2 曾把新便签放在被点便签旁边的固定位置，连续点同一张会完全重叠；LavaDesk 式的每张只错开 28/22px 叠放也仍然重叠太多，都已废弃。
- **进行中**：顶栏 ▷ 写入 `startedAt`（再点清除），只有在桌面上的便签可以开始；撕下时保留（以后可算从开始到完成的用时），贴回时清除。`isInProgress` = 有 `startedAt` 且仍在桌面。进行中的便签：一圈模糊的光晕贴着纸张下半部、溢出到透明边距里（`.note__glow`，`pointer-events: none` 让命中测试忽略它，边距照样穿透；模糊在 30px 以内结束，这是最大纸张倾斜后四角处仍保留的边距），纸内从底边升起一层光（`.note__doing-wash`），两者一起呼吸（3.4 秒）；纸张的深色投影同时变浅，免得把光压暗。顶栏左侧显示“进行中 · 10月9日 14:30 起”（窄时只显示日期或不显示），记开始时间而不是计时，因为很多事要做好几天；标记从播放三角换成呼吸的圆点加一段绕圈的弧，顶栏下沿有一道光每 4 秒流过一次。动画只用 transform 和 opacity，由合成器完成，开启减少动态效果时停止。颜色跟随纸色：每种纸色定义 `--doing`（深色，用于文字、标记、方框）和 `--doing-glow`（鲜亮，用于光晕、光带），1.1.0 曾统一用琥珀色。管理窗口里原来叫“进行中”的筛选（仍在桌面的便签）改名“未完成”，避免和这个标记混淆。
- **正文是唯一的内容来源**：标题、预览和图片数由正文派生，不再有可以和正文不一致的“任务标题”。纯图片、清空内容都能正常保存。
- **图片单独存文件**：渲染进程把图片（超过 3MB 或边长超过 2000px 时缩成 WebP）交给主进程，主进程按文件头识别类型、按 SHA-256 命名保存，正文里只有 `lavanote://asset/<hash>.<ext>`。编辑器只接受这种地址的图片，粘贴网页不会加载远程图片。7 天以上无人引用的图片在启动后清理。
- 正文超过 2MB 时拒绝保存并提示，不截断。

## 废弃

⋯ → 废弃写入 `abandonedAt` 并隐藏，和撕下（`archivedAt`）互斥：一张便签要么在桌面（可见或收起），要么完成，要么放弃（`noteState`）。文件里两者都有时保留更早的那个。两种离开走同一条流程：主进程记下离开方式，窗口播放撕下或揉皱动画后回报（2.5 秒兜底），再写入时间。“重新贴回”同时清除两者。

## 勾选清单的时间线

勾选项（`TrackedTaskItem`）在正文里带 `tid`、`createdAt`、`startedAt`、`checkedAt` 四个属性。编辑器的 `appendTransaction` 插件在每次改动后补齐：新项或复制出来的重复 id 换新 id 并记当前时间，勾上记勾选时间，取消勾选清空；属性不随回车拆分（`keepOnSplit: false`），撤销时和文字一起恢复。没有这些属性的旧项在载入时用便签的创建/修改时间补上，统计端（`extractTasks`）用同样的回退。

方框有三种状态：待办、进行中（未勾选且有 `startedAt`，琥珀色方框加呼吸圆点，与便签的进行中标记一致；整行有一条从方框向右渐淡的光带一起呼吸，第一行文字带一点同色）、完成。单击仍是原生复选框的行为（完成 ⇄ 未完成），不改变原有习惯；右键方框（`toggleTaskDoing`）在待办和进行中之间切换，已完成的右键回到进行中。勾选时保留 `startedAt`，所以取消勾选会回到进行中。方框由 `label` 的伪元素画出，真正的复选框透明地盖在上面，点击和编辑器的处理都不变。

## 语言模型

- 配置与 LavaTranslate 相同：`src/shared/ai.ts` 是服务商目录（接口地址、Key 格式、推荐模型、关闭思考的参数），`ai-settings.json` 按服务商分别保存 Key、地址、模型；Key 用 `safeStorage` 加密，界面只拿到打码形式，回传打码值表示未修改。ChatGPT 会员登录（PKCE + 本机回调）、从 Codex / CC Switch 导入、models.dev 价格（安装包内置快照 + 3 天缓存）都照搬 LavaTranslate。
- 只有主进程联网（`openai` SDK + Electron `net.fetch`，走系统代理）。先试 Responses 接口，服务商没有就改用 Chat Completions 并记住；推理强度从 none 逐档回退。渲染进程的 CSP 不变。
- 便签内容只在用户点翻译或生成解读时发出，日志只记错误类型。

### 翻译

正文按文本块编号成段（段落、标题、列表项、勾选项、表格单元格各一段），模型按 JSON Lines `{"i":n,"t":"…"}` 逐段返回，边收边显示。替换时把译文写回同一位置，列表、勾选状态、表格、图片不动；整块统一的格式保留，混合的行内格式丢弃。替换前比对翻译时的正文快照，改动过就要求重新翻译。选中的文字按行翻译，空行保留。目标语言“自动”：中文译成英语，其他译成简体中文。

翻译面板出错时（还没配置模型、Key 被拒）有“重试”；模型设置一改，主进程向所有便签窗口广播 `NOTE_AI_CHANGED`，处于出错状态的面板自动重新翻译，不会留着旧提示。模型漏掉的段落在完成后照常显示原文，并提示“有 N 段没有译出”。

AI 配置页里 API Key 卡片和模型列表都按服务商设 key 以便切换时重建，两者的 key 必须不同（`key:` / `models:` 前缀）：1.1.1 及以前两者同用服务商名作 key，React 遇到重复 key 会留下旧组件，每切换一次服务商就多出一张 Key 卡片。

## 统计

数字全部由 `src/shared/stats.ts` 按时间戳精确计算（周从周一开始，本地时间）：新写、撕下、废弃、勾选新增/完成、期末进行中、中位用时，以及生命线、节奏网格。模型只负责语义部分（`src/shared/insights.ts`）：把一个周期里的便签（最多 60 张，每张约前 260 字，用 N1、N2 代替 id）连同算好的数字发给模型，要求返回固定结构的 JSON（标题、总结、主题、节奏、发现、建议、被搁置的便签），解析时容忍代码块和多余文字，再把代号映射回便签。结果按“粒度:周期起点”缓存在 `ai-insights.json`（最多 80 条）。

图表是手写的 SVG（`src/renderer/manager/charts.tsx`），不引入图表库。系列颜色取经过 CVD 校验的蓝 / 橙 / 青三色（在纸色底 #fffaf0 上全部两两可分；青色对比度不足 3:1，因此每张图都有图例、少量直接标注和提示框，进与出另有数据表）；生命线用便签自己的纸色，结局用 ✓ / ✕ 图标表示。

## 托盘菜单

Windows 的原生弹出菜单左侧固定留一列给勾选标记和图标，菜单里没有图标时就是一大块空白，所以 Windows 上右键托盘图标打开 LavaNotes 自己画的菜单（`src/main/tray-menu.ts` + `src/renderer/tray`）；macOS / Linux 仍用原生菜单。

- 一个透明、无边框、置顶（`pop-up-menu` 层级）、不进 Alt+Tab 的窗口，比纸卡大一圈留给阴影（`TRAY_SHADOW` 与 tray.css 的 `--shadow` 一致）。光标停在托盘图标上时就预先加载页面，首次右键也能立即弹出；10 分钟没用就销毁，交还渲染进程。
- 每次打开，主进程把状态（开机启动、待安装的更新、桌面上的便签数和进行中的数量）发给页面；页面在隐藏状态下同步渲染并回报纸卡尺寸，主进程再按光标位置摆放：默认在光标上方向右展开，放不下就翻到左边或下方，并留在工作区内。先以透明度 0 显示一帧再显现，避免闪出上一次的内容。
- 失焦、Esc、或在纸卡外按下鼠标（轮询 `GetAsyncKeyState`，因为 Windows 不一定把焦点交给它）都会关闭。“开机启动”是开关，切换后菜单不关闭。
- 页面 800ms 内没有回报尺寸或加载失败时，退回原生菜单。

## 存储

`NotesService` 是唯一的状态来源，不依赖 Electron，可以直接单元测试。索引、设置、每篇正文分别用 `KeyedWriter` 合并写入：失败时保留最新值稍后重试，退出前 `flush()`。退出、隐藏便签前主进程会先请便签窗口把编辑器里尚未保存的内容发回来。

## 验证

- `npm test`：类型检查、lint、`tests/*.test.mjs` 单元测试（模型、几何、存储、图片、NotesService、统计、翻译分段与回填、模型配置与解读解析）。
- `npm run test:smoke`：构建后用独立 userData 启动应用，驱动真实窗口检查渲染进程、命中测试、渲染、打字保存、表格、图片加载、缩放、层级、撕下归档、勾选项时间、二级菜单、废弃、管理窗口（默认打开统计页、便签管理的状态筛选）、统计页和 AI 配置页。模型相关的检查连接进程内的模拟 OpenAI 兼容服务（`src/main/smoke-ai.ts`，没有 Responses 接口、SSE 流式返回），走完翻译→替换和 AI 解读，不访问外网。另外检查便签的进行中标记、勾选项右键进行中，以及（Windows 上）托盘菜单在工作区内弹出、开机启动开关原地切换、Esc 关闭。CI 在 Linux（xvfb）和 Windows 上运行，发布前在 Windows 上再跑一次。
- Windows 上的冒烟测试另外在便签后放一个红色窗口：截屏确认透明边距透出红色、纸面正常绘制，并用真实鼠标点击确认边距点击落到后面的窗口、纸面点击落到便签（`src/main/smoke-windows.ts`；运行环境无法截屏或移动光标时记为跳过）。
- 钉在桌面、Win+D / Win+M、输入法和多屏混合 DPI 仍需要在真实 Windows 上验收。
